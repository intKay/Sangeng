# v1.4.0 方案 · 留灯（A Light Left On）

> 下一版的中心不是加场景，而是让已经做好的场景被看见。
> 基线：v1.3.0（`f5fd38b`，网页/桌面/手机通用）。本文件是方案，不是已实现功能。
>
> 已确认决策（2026-10-20）：默认提示等级 = **沉浸**；v1.4.0 **不做**“降低惊扰”；夜路补 4 个路边查看交互；新增结局收集与重开提示。

## 1. 判断：现在缺的不是内容，是“看见内容的路径”

v1.3.0 已经有三篇完整短篇、稳定的 PS1 美术、原创声音、手机触控和可发布包。问题集中在体验层：

- **目标只有一行**：玩家知道“找三张字条”“让镜中的房间一致”，但不知道下一步在哪个房间、镜中哪一类东西不一样、夜路下一盏灯在哪个方向。
- **可选内容很多，但没有记录**：门后有近 20 个可查看的旧物，镜中有 5 个澡堂旧物与 8 个解谜物件，夜路的路牌/牌位/纸钱没有交互入口。玩家错过之后不会知道自己错过了什么。
- **卡住时没有梯子**：门后与夜路基本没有“停留一段时间后的提示”；镜中只有 38s/82s 两条提示；玩家可能在同一间房里转到放弃。
- **通关后没有“完成感”**：结局页只有“再走一遍/返回入口”，入口页没有进度；玩家不知道“我这次看见了什么、还差什么”。
- **v1.3.0 验收也明确写了**：自动化只验证了核心交互，没有真人完整通关；指引与发现是当前最大的未知数。

所以下一版的主题是 **“留灯”**：不把玩家拽到目标前，而是在他可能错过的地方留一盏灯、一张纸、一点水汽，让他自己看见。

## 2. 目标与非目标

### 目标

1. 第一次玩的玩家，不看攻略也能在 10–15 分钟内走到结局；卡住时能在不破坏气氛的前提下得到帮助。
2. 想深入玩的玩家，能知道每篇有哪些旧物/线索/结局，并能在第二遍有目的地寻找。
3. 通关后留下可见的记录：本篇发现数、结局、印章；三篇完成有合集层面的“三更已满”。
4. 保持现有的极简 HUD、PS1 低分辨率、颗粒、暗部与安静节奏；不把游戏变成清单或导航游戏。
5. 所有进度只存在本地 `localStorage`，不上传、不联网、不做遥测。

### 非目标（本版不做）

- 不新增关卡、不重做场景、不改变三篇的核心机制与结局。
- 不做中途存档/读档；仍是 6–10 分钟单局，死亡就地重试。
- 不做账号、云存档、成就服务器、排行榜。
- 不做完整章节选择/回看（可作为 v1.4.1 的后续，见 §9）。
- 不把提示做成常驻箭头/自动寻路；默认不显示 3D 标记。

## 3. 设计支柱

1. **先环境，后文字，最后才是标记**：灯、声音、水汽、纸响先引导；文字提示只在停留后出现；3D 标记只在高提示档位出现。
2. **提示是“关心”，不是“教程”**：提示文案保持角色/场景口吻，例如“客厅的灯还亮着，桌上压着一张纸”，而不是“目标：拾取字条”。
3. **发现是记录，不是打卡**：不弹成就、不刷屏；第一次看到时只在左下角留一行墨迹“记下：旧照片”，可在设置里关闭。
4. **完成感来自回看**：结局后告诉玩家“你看见了什么”，入口页留下印章；不追加强制内容。
5. **失败也要能继续**：死亡页保持“再来一次 / 返回入口”；手记里可主动要提示，不自动弹、不降低难度。

## 4. 系统一：分层指引（Guidance）

### 4.1 目标卡

保留一行目标，但拆成“做什么 + 在哪里”：

| 篇目 | 当前目标 | 第二行（仅一句） |
|---|---|---|
| 门后 | 回到 503 / 找第 X 张字条 / 回卧室 | 走廊尽头 / 客厅、厨房、书架 / 门缝底下有光 |
| 镜中 | 让镜中的房间与现实一致（还差 N 处） | 第 X / 3 回合 |
| 夜路 | 点亮五盏灯笼（X/5）/ 到土地庙 | 雾里的灯 / 前方檐角 |

第二行只在目标变化或停留较久时出现，不常驻。

### 4.2 提示等级（设置项，默认“沉浸”）

| 等级 | 行为 |
|---|---|
| 沉浸（默认） | **无自动文字提示**；环境线索优先；暂停→手记→“线索”里可主动点“要一句提示”，玩家自己决定何时求助 |
| 标准 | 停留 35s 模糊提示；75s 指向某类物件；120s 一次环境脉冲（灯闪、镜面反光、灯笼亮一下） |
| 引导 | 20s/45s/70s 递进；允许一次短暂方向标记；适合首次接触第一人称/移动端玩家 |

- 默认沉浸意味着“不打扰”，不是“无帮助”：帮助被收进手记，由玩家主动打开；这样既不破坏气氛，也避免卡死。
- 提示不揭示解法：镜中只说“毛巾的位置不一样”，不说“把毛巾挂到左边钩子”；门后只说“餐桌上有一张纸”，不说“去按 E”。
- 提示文本按“停留 + 无新发现 + 死亡次数 + 错误交互次数”综合触发；玩家在移动/看新物件时暂停计时，避免打断探索。
- 每次进入新房间/新回合重置提示计时；同一提示不重复超过两次。
- 提示队列复用现有字幕系统，不新增 HUD 元素。

### 4.3 环境引导（不加 UI 的主要手段）

- **门后**：字条所在房间留一盏灯/电视雪花/照片反光；第三轮追逐时卧室门缝的光更明显；她出现前先有呼吸与楼板声。
- **镜中**：与目标不一致的物件在镜面上有一层很轻的水汽/反光脉冲；手印出现时伴随一声水汽；回合开始时镜面短暂“呼吸”一次。
- **夜路**：下一盏灯的暖光在雾里可见；土地庙的檐角灯先于建筑出现；纸人靠近时纸响方向性更强。
- 这些是内容侧可做的微调，不需要新模型；优先用现有灯光、音效、材质。

### 4.4 卡住检测与死亡页

- 沉浸默认下不自动弹提示：连续 90s 无新发现/无目标进度时，只在暂停菜单的手记图标上点一个小墨点；180s 手记里出现“要一句提示吗？”，由玩家自己打开。
- 标准/引导档位才使用定时字幕提示。
- 死亡页保持现有“再来一次 / 返回入口”，**v1.4.0 不做“降低惊扰”**；死亡后仍保留已有进度与手记。

## 5. 系统二：发现册（Journal）

### 5.1 入口与形态

- 暂停菜单新增第三项 **“手记”**（继续 / 手记 / 设置 / 返回入口）。
- 手记是一张暗色纸，保持现有宋体/楷体与金色墨迹；只分三栏：
  - **当前**：目标、第二行提示、已走轮次
  - **发现**：分组卡片 + 计数，未发现条目显示模糊提示而不是“???”空白
  - **线索**：已读字条/照片/海报的摘要，可回看
- 手机端全屏滚动，按钮 ≥44px；不改变游戏 HUD。

### 5.2 发现条目

- 每条有 `id / group / title / summary / hint / discovered`。
- 第一次触发：左下角一行墨迹“记下：旧照片”，2.5s 消失；可用设置关闭。
- 未发现条目不剧透：显示“客厅墙上的某样东西”“澡堂里被改过的纸”等模糊提示。
- 计数按组显示，例如：
  - 门后：`主线 5/7 · 旧物 9/18 · 她 1/3`
  - 镜中：`回合 2/3 · 澡堂旧物 3/5 · 镜中差异 5/8`
  - 夜路：`灯 3/5 · 路边 1/4 · 土地庙 0/1`；结局单独显示 `结局 0/2`
- 条目数量以最终内容清单为准；不在 HUD 常驻总数，避免清单感。

### 5.4 当前结局清单（v1.3.0 实况）

- **门后 1 个**：读完卧室的信，结局唯一。
- **镜中 1 个**：第三次对齐后的镜面碎裂，结局唯一。
- **夜路 2 个**：**《你回头了》** 与 **《你没有回头》**，两个平级结局，目前**没有“真结局”标记**。
- 死亡页不是结局，不计入结局收集。
- 结局单独存 `endings: []`，不混进发现数；未来若增加隐藏/真结局，用 `isTrue` 元数据标记，未解锁时按“结局 X/Y”隐藏名称。
- **不把现有夜路两结局硬分高低**：这会改变现在的叙事语义；如果确实要真结局，建议作为 v1.4.1 的内容新增并另写文本。

### 5.5 进度持久化

- `localStorage` 键：`sangeng.progress.v1`（版本号用于迁移；损坏时回退为空，不阻塞游戏）。
- 每篇记录：`discovered: {}`、`completed: bool`、`endings: []`、`plays`、`deaths`、`bestTime`。
- 合集记录：`seals: {door, mirror, nightroad}`、`allComplete`。
- 设置里提供“清除进度”，二次确认；不影响设置。

## 6. 系统三：通关与完成感

### 6.1 结局页

在现有结局文字下方增加一段轻量统计（不抢文字）：

```
这一次
发现 14 / 28 · 主线 5 / 7 · 旧物 9 / 18 · 她 1 / 3
结局：你终于回来了（1 / 1）
```

按钮：`再走一遍` / `看手记` / `返回入口`。
- 不显示“你错过了 X”这种责备式文案，只显示“还有 9 件旧物没有带走”。
- 夜路显示 `结局 1 / 2`，并列出已解锁结局名；镜中显示“三次对齐 / 镜中人走到第几步”。

### 6.2 入口页

- 每张海报卡片底部增加一行小字 + 印章位：
  - 未完成：`尚未还家` / `尚未看清` / `尚未走完`
  - 已通关：门后/镜中 `已还家 · 发现 14/28`；夜路 `已走完 · 发现 7/10 · 结局 1/2`，卡片右下角盖一枚朱红小印。
  - 三篇都通关：入口页底部出现 `三更已满` 小条，三枚印章并排；不新增玩法。
- 若三篇所有结局都解锁，`三更已满` 旁再加一行 `全结局` 小字；不另做成就系统。
- 进度只读自本地存储；无账号。

### 6.3 结局收集与重开提示

当前只有《夜路》有 2 个平级结局（回头 / 不回头），门后/镜中各 1 个，**没有真结局**。本版按“结局收集”处理，不硬造真结局：

- 结局页显示 `结局 1 / 2`（夜路）或 `1 / 1`（门后/镜中），已解锁结局列出标题，未解锁显示 `？？？`。
- 夜路第一次结局后，结局页底部多一行：
  - 若第一次是《你回头了》→ “另一条路：这次别回头。”
  - 若第一次是《你没有回头》→ “另一条路：这次回头看看。”
- 玩家点“再走一遍”时，在开局载入/标题处再显示一次同一句提示（一次性，不打断游戏内选择）；不提前剧透具体按键，进入庙前后由现有选择提示承担。
- 门后/镜中只有 1 个结局，不显示“另一条路”提示，只显示 `结局 1/1`。
- 以后若加入真结局：在 `endings` 元数据里标记 `isTrue`；未解锁时，重开提示只指向“还有一个结局”，不点名；全收集后才显示真结局名。

### 6.4 章节回看（后续，不阻塞 v1.4.0）

- v1.4.1 可加“回看模式”：门后从第三轮、镜中从第三回合、夜路从土地庙开始；不改变单局结构。
- v1.4.0 先做“再走一遍 + 手记”，这样已经能完成“知道还差什么、下一遍去哪里找”。

## 7. 具体指引脚本（示例）

> 以下句子用于：沉浸档玩家在暂停手记里主动点“要一句提示”；标准/引导档的定时提示。默认沉浸下不会自动弹出。

### 门后

| 触发 | 提示（示例） |
|---|---|
| 开局 20s 未进 503 | “走廊尽头，503。你的钥匙还在口袋里。” |
| 进入 503 30s 未拿字条 | “有人常待的地方：桌边、厨房、书架。” |
| 60s 未拿第 1 张 | “客厅的灯还亮着。桌上压着一张纸。” |
| 拿到第 1 张后 40s 未回 503 | “门又开了。回去看看，屋里少了什么。” |
| 第 2 轮 60s 未拿第 2 张 | “厨房的门半掩着。她总把要紧的东西放在碗柜上。” |
| 第 3 轮追逐 20s | “看着她，她不会动。卧室门在走廊另一端。” |
| 连续死亡 2 次 | 手记里出现一句“需要提示吗？”，不自动弹、不降低难度。 |

### 镜中

| 触发 | 提示（示例） |
|---|---|
| 回合开始 25s | “镜子里的房间，和这边不一样。先找最显眼的那处。” |
| 50s | 指定一个剩余物件类别：“毛巾/阀门/灯/凳子……” |
| 90s | 该物件在镜面上出现一次短暂反光；不自动改变状态 |
| 错误交互 2 次 | “每错一次，镜中人靠近一步。先看清再动手。” |
| 死亡重试 | 保留回合进度，手记显示“已对齐 X 处 / 本回合还差 Y 处”。 |

### 夜路

| 触发 | 提示（示例） |
|---|---|
| 开局 15s | “雾里有灯。先看见光，再看见路。” |
| 60s 未点到下一盏 | “下一盏灯在你左/右前方。跟着暖光走。” |
| 纸人靠近 | 纸响/方向性提示；手记记录“它跟得更近了” |
| 上香后 | 明确“按 E 回头 / 按 W 继续向前，别回头”，不自动选择 |
| 第一次结局后 | “另一条路，你还没有走。” |

## 8. 技术方案与交接

### 8.1 引擎（Codex 负责）

建议新增三个小模块，全部不改变现有 HUD/渲染：

1. `engine/progress.js`
   - 版本化 `localStorage` 读写、损坏回退、清除进度。
   - API：`game.progress.load() / save() / get(gameId) / mark(gameId,id) / summary(gameId) / unlockSeal(gameId)`。
2. `engine/discovery.js`（也可并入 progress）
   - 内容侧注册目录：`game.discovery.define([{id, group, title, summary, hint}])`。
   - `game.discovery.mark(id)` 返回 `{first:true}`，触发一次墨迹 toast；重复查看不重复计数。
   - `game.discovery.counts()` 给 HUD/结局页/入口页。
3. `engine/hints.js`
   - 输入：当前目标、房间/回合、最近交互、停留时长、死亡/错误次数。
   - 输出：字幕提示或一次环境脉冲（由内容侧提供回调）。
   - 设置项 `hintLevel` 持久化。
4. UI 扩展（`engine/ui.js` + `engine.css`）
   - 暂停菜单“手记”、手记三栏页、结局统计区、入口页进度印章、设置中的提示等级/发现提示开关。
   - 触屏与安全区适配沿用现有样式。
5. 入口页（`index.html`）
   - 读取合集进度，渲染卡片小字/印章；不引入框架，原生 DOM。

### 8.2 内容（我方负责）

- 三篇 `game.js` 里注册发现目录、触发 `mark`、编写提示脚本与环境引导。
- 手记摘要文本、结局统计文案、入口页的“未完成/已完成”文案。
- 夜路新增 2–4 个路边查看交互（路牌、牌位、纸钱、田埂旧物），复用现有模型；若需要新增小物件，只加极低多边形/平面，不扩场景。
- 调整少量灯光/音效触发，让“留灯”在场景里成立；不改材质与整体色调。

## 10. 验收标准（v1.4.0）

### 体验

- 第一次接触的 3–5 名玩家（不看攻略）：
  - 首次交互 ≤ 60s；
  - 门后 10–15 分钟内到结局，镜中 10 分钟内，夜路 15 分钟内；
  - 至少 2/3 的玩家在第二遍能主动找到至少 3 个第一遍错过的旧物；
  - 没有人因为“不知道下一步”而退出。
- 提示系统：正常推进时不触发；沉浸档默认**自动提示为 0**，只能从手记主动取提示；标准档约 35s 出现第一句；三档设置可切换并持久化。
- 手记：每条发现准确；未发现不剧透；数字与实际一致；手机可滚动、可关闭。
- 结局页：统计正确；能回看手记；能再走一遍。
- 入口页：三篇进度与印章正确；清进度后恢复未完成状态。

### 技术

- 0 console error、0 failed request（沿用 v1.3.0 验收脚本）。
- `localStorage` 损坏/禁用时不崩溃，游戏仍可完成。
- 触屏与键鼠都能打开手记、切换提示等级。
- 网页包/桌面包都能保存进度；打包体积增量 < 2%。
- 不改变现有 62 张贴图/音频 manifest；不新增 3D 场景。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 指引过强，破坏恐怖/孤独感 | 默认“沉浸”，无自动提示；环境提示优先；文字只由玩家在手记里主动取；高指引是可选设置 |
| 手记变成清单，玩家只刷条目 | 不常驻总数；不弹成就；未发现只给模糊提示；结局不做“全收集”强制 |
| UI 变复杂/手机遮挡 | 手记只在暂停中；不新增 HUD；沿用现有安全区与滚动样式 |
| 本地存档损坏/清理浏览器 | 版本化 key、损坏回退、设置中可手动清除；不依赖存档完成流程 |
| Codex 引擎排期 | 先冻结 API，内容侧用假数据开发；UI 可分批合并 |
| 剧透 | 提示只指位置/类别，不给状态答案；未发现卡片打码 |
